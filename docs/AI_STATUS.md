## 最終更新

Claude Codeが、2026-09-26 15:46生成分の`room/data/candidates.json`で新しく見つかった商品タイプ（ペット用品・電池・家電の一部・ベビー用品の一部・食品の一部）の紹介文誤分類・数量表現の不自然さを修正した。**商品選定ロジック・ランキング・10商品・item_code・順番・評価・レビュー数・全ジャンルの商品タイプ判定の3段階構造は変更していない**。商品タイプ判定・数量判定・ハッシュタグを拡張する形で対応した。

## 1. 根本原因

1. **新しい商品タイプがPRODUCT_TYPE_TEMPLATES未登録だった**：鹿角（ペット用品）・フードボウル・ボタン電池・サーキュレーター・扇風機・紙おむつ・おしりふき・エコバッグ・うどんのいずれも登録がなく、DEFAULT_CATEGORYの汎用文、または「健康」「家電」カテゴリーの汎用文になっていた。
2. **同じ商品名に複数の商品タイプキーワードが混在する商品があった**：サーキュレーター商品の商品名に「扇風機」も含まれ、逆に扇風機商品の商品名にも「サーキュレーター」が含まれていたため、商品タイプ判定がPRODUCT_TYPE_TEMPLATESの登録順でしか判定できず、商品名の中でどちらが実際の商品本体かを区別できていなかった。
3. **数量抽出が「個数×個数」の組み合わせ表記（例：「80枚×40個」）に対応しておらず**、先頭の単位だけを拾って「80枚」に落としてしまっていた。「20P」という個数表記にも対応していなかった。
4. **「選べる」「種類」という言葉だけで“いろいろな種類のセット”と判定していたため**、「1種類を選べる」（＝サイズを1つ選ぶ、という意味）の商品でも誤って“アソート”のような表現になっていた。同様に、既存の複合数量表記（例：「380g×4セット」）でも、末尾の単位だけで判定すると「セットセット」の重複や誤ったアソート表現が生成される潜在バグが見つかった。
5. **FEATURE_CLAUSESの「詰め替え」の言い回しが「ごみを減らしやすい」という確認できない環境効果まで断定していた**。

## 3. 数量判定の改善内容

1. 「個数×個数」の組み合わせパターンを追加（例：「80枚×40個」を「80枚」だけに落とさない）。
2. 「20P」のような個数表記（P）に対応。
3. 複合数量表記（×・+を含む表記）は、単位の末尾だけで言い換えず、従来通り`{数量}で使いやすい`のままにする判定を追加。既存の複合表記＋「1種類を選べる」で「セットセット」の重複や誤ったアソート表現が生成される潜在バグを修正した。
4. 「1種類を選べる」を“いろいろな種類のセット”から除外する`_SINGLE_CHOICE_PATTERN`を追加。複数の種類から1つだけを選ぶ意味であり、いろいろな種類が同時に届くセットではないため、通常の個数セット表現にとどめる。
5. 単純な個数（本/個/枚/袋/セット/包/パック）で、いろいろな種類のセットでもない場合の言い回しを「◯◯で使いやすい」から「◯◯セット」に変更（すでに「セット」を含む場合は重複させない）。「10個セット」「2個セット」という指定の言い回しに対応。
6. 重さ/容量×個数の組み合わせ表記の末尾に「◯人前」が続く場合、一緒に抜き出すよう拡張（例：「170g×4袋 8人前」）。

いずれも単位・周辺語による汎用的な判定であり、特定商品のハードコードではないため、今後の同系統商品にも適用される。

## 4. カテゴリーより商品本体を優先する仕組み

既存の3段階構造（①具体的商品タイプ→②ジャンル別安全テンプレート→③安全フォールバック）は変更していない。ボタン電池2件は検索カテゴリーが「健康」だが、①の具体的商品タイプに一致するため、商品本体を優先した紹介文になる。サーキュレーター・扇風機も「家電」という汎用カテゴリーではなく①が優先される。

同じ商品名に複数の商品タイプキーワードが混在する場合の判定を、`_iter_product_type_keyword_matches()`をPRODUCT_TYPE_TEMPLATESの登録順ではなく、商品名の中でキーワードが実際に登場する位置が早い順に判定するよう修正した（商品タイトルは通常、最初に主要な商品名を書くため）。これにより、サーキュレーター商品（商品名の先頭が「サーキュレーター」）はサーキュレーターのテンプレート、扇風機商品（商品名の先頭が「扇風機」）は扇風機のテンプレートを、それぞれ正しく選ぶようになった。既存の付属品判定（「リモコン付き」等、description-genre-002）の仕組みと組み合わせて動作し、その回帰テストは無修正のまま成功している。
