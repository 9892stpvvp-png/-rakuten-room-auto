# 実装方針・調査結果（設計ドキュメント）

このドキュメントは、「楽天ROOM運用の自動化」をどこまで・どうやって進めるかをまとめたものです。
専門用語はできるだけ避けていますが、わからない言葉が出てきたら遠慮なく質問してください。

## 1. 結論（まずここだけ読めばOK）

- 商品を探す・条件で絞り込む・重複をチェックする・紹介文を作る・候補一覧を保存する
  → **公式のデータだけを使い、自分のパソコン（このプロジェクト）の中だけで完結する処理なので、自動化して問題ありません。**
- 楽天ROOMへ実際に投稿するボタンを押す部分
  → **自動化しません。** 楽天ROOMの利用規約で「機械的に投稿する行為」がはっきり禁止されているためです。
  最終的に「コピペして投稿する」のは人間（あなた）が行います。

つまりこのプロジェクトは「投稿の下ごしらえを全自動化し、投稿ボタンを押す瞬間だけ人間が行う」という設計にします。

## 2. 調べたこと

### 2-1. 楽天ROOMの利用規約について

楽天ROOMの利用規約（禁止事項）には、次のような趣旨の記載があります。

> スクリプトその他のプログラムを実行する等の方法により、機械的に投稿、コメント等をする行為を禁止する

参考：
- [利用規約 - ROOM - 楽天市場](https://room.rakuten.co.jp/signup/agreement)
- [投稿のガイドライン - ROOM - 楽天市場](https://room.rakuten.co.jp/info/help/guideline/01.html)

つまり「ROOMへの投稿を、プログラムが自動でボタンを押して行う」ことは規約違反にあたる可能性が高く、
アカウント停止（BAN）のリスクがあります。世の中には「自動投稿ツール」を作って公開している人もいますが、
規約違反のリスクを利用者が負う形になっているため、このプロジェクトでは採用しません。

### 2-2. 楽天が公式に提供しているAPI（データ取得の仕組み）

楽天には「楽天ウェブサービス（Rakuten Web Service, 通称RWS）」という、開発者向けに公式に提供されている
データ取得の仕組み（API）があります。この中の「楽天市場 商品検索API（Ichiba Item Search API）」を使うと、
以下のような情報を**合法的に**取得できます。

- 商品名、価格、商品ページのURL、商品画像のURL
- レビュー平均点（reviewAverage）
- レビュー件数（reviewCount）
- ショップ名、ジャンル（カテゴリ）情報
- 商品の説明文（キャッチコピー）

参考：
- [Rakuten Web Service: Rakuten Ichiba Item Search API](https://webservice.rakuten.co.jp/documentation/ichiba-item-search)

利用するには「楽天会員登録」と「楽天ウェブサービスの利用登録（無料）」を行い、
「アプリID（applicationId）」と呼ばれる鍵となる文字列を発行してもらう必要があります。
これは合言葉のようなもので、他人に見せたり、GitHubなどにそのまま公開したりしてはいけません。

このAPIには「1秒間に送れるリクエストの数」などの利用制限（レート制限）があります。
短時間に大量アクセスすると制限にかかったり、利用停止になる可能性があるため、
プログラム側で「少し間隔を空けて呼び出す」処理を必ず入れます。

> 補足：APIのレスポンスに「楽天ROOM対象商品かどうか」を直接示す項目は現時点では見当たりませんでした。
> 実務上は「楽天市場で購入できる商品はROOMにも投稿できる」という前提で問題ありませんが、
> 実際に運用しながら例外がないか確認していきます。

### 2-3. ログイン・認証の扱いについて

このプロジェクトで「ログイン」が必要になるのは、商品データを取るための
「楽天ウェブサービスのアプリID」だけです。これはIDとパスワードでログインするタイプの認証ではなく、
発行された文字列（鍵）をプログラムに渡すだけの仕組みです。

- 楽天ROOM自体へのログイン（メールアドレスやパスワード）は、このプロジェクトでは**一切扱いません**。
  自動投稿をしない設計にしているため、ROOMにログインする必要自体がないからです。
- アプリID（鍵）は `.env` という設定ファイルに書き、`.gitignore` でGitの管理対象から除外します。
  これにより、間違ってGitHubに公開してしまう事故を防ぎます。

### 2-4. BANリスクを避けるための方針まとめ

| やること | 安全性 |
|---|---|
| 公式API（楽天ウェブサービス）でデータ取得 | ◎ 安全（利用規約で認められた使い方） |
| 取得したデータをローカルで条件判定・重複チェック | ◎ 安全（自分のPC内の処理） |
| 紹介文をテンプレートで自動生成 | ◎ 安全（自分のPC内の処理） |
| 候補一覧をファイルに保存し、人間が見て選ぶ | ◎ 安全 |
| ROOMのサイトを自動操作してログイン・投稿する | × 行わない（規約違反・BANリスク） |
| ROOMのページをスクレイピング（プログラムで読み取り）する | × 行わない（規約違反・負荷をかけるリスク） |

## 3. 自動化する処理の全体像

```
[1] 商品候補の収集
     楽天ウェブサービスAPIに「掃除」「収納」「キッチン 便利グッズ」などのキーワードで検索をかけ、
     商品情報（価格・レビュー評価・レビュー件数など）を取得する。

        ↓

[2] 条件判定（フィルタリング）
     以下の条件を満たす商品だけを残す。
       ・レビュー評価が4.0以上
       ・レビュー件数が100件以上
     （広告対象かどうか、ポイント倍率、ランキング入賞、メディア掲載の有無は判定材料にしない）

        ↓

[3] 重複チェック
     「過去に紹介した商品の一覧（data/posted_items.json）」と商品IDを突き合わせ、
     すでに紹介した商品を候補から除外する。

        ↓

[4] 紹介文の自動生成
     商品名・特徴・価格などから、
       ・自然な日本語の紹介文
       ・箇条書き（特徴のポイント）
       ・ハッシュタグ
     を1つの文章ブロックにまとめる（500文字以内、コピペしてそのまま使える形）。

        ↓

[5] 投稿候補一覧の保存
     [1]〜[4]の結果を1つのファイル（CSVまたはJSON）にまとめて保存する。
     ここまでは完全自動。

        ↓

[6] 人間による確認・投稿
     保存された候補一覧を人間が見て、内容と商品画像が合っているか確認したうえで、
     良いと思った紹介文をコピーし、楽天ROOMアプリ／サイトに手動で貼り付けて投稿する。
     投稿し終えたら、その商品IDを data/posted_items.json に追加する
     （これも将来的には「投稿しました」ボタンひとつで自動記録できるようにする想定）。
```

## 4. 開発の進め方（フェーズ分け）

最初から全部を作ろうとすると難しいので、小さく段階を踏みます。

- **フェーズ0（今回）**：設計・調査・最小構成のひな形作成（コードは書くが実行はしない）
- **フェーズ1**：楽天ウェブサービスAPIから実際に商品を取得できるようにする（動作確認込み）
- **フェーズ2**：条件判定・重複チェック・紹介文生成をつなげて、候補一覧ファイルを出力できるようにする
- **フェーズ3**：使い勝手の改善（キーワードの追加、除外ワード、生成される文章の質の調整など）
- **フェーズ4（任意）**：投稿済み管理を楽にするための、人間向けの簡単なチェック用画面や記録の仕組み
  （※ここでも「ROOMへの自動投稿」は行いません）

## 5. なぜ「広告対象・ポイント倍率・ランキング入賞・メディア掲載」を除外理由にしないのか

これらは「商品そのものの良し悪し」とは関係のない、販促上の情報だからです。
今回はあくまで「レビュー評価・レビュー件数・売れ行き」という客観的な指標で商品を選ぶ設計にしています。
